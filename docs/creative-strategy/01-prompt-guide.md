# 01. プロンプト設計ガイド — Opus への指示の基本形

戦略系の相談を AI(Claude Opus など)に投げるときの「型」。ここを押さえると、以降のひな型すべての精度が上がる。

## コンテキストの2層構造(マスターデータ→派生物の発想)

HACCP システムと同じ設計思想で、AI に渡す自己文脈を「変わらないもの」と「変わるもの」に分離する。

| 層 | 内容 | 置き場所 | 更新頻度 |
|---|---|---|---|
| **[ペルソナ]** | 人物像・プロジェクト・作業スタイル | リポジトリ直下 `CLAUDE.md` の「オーナーコンテキスト」節 | 大きな変化時のみ(数ヶ月に1回) |
| **[スナップショット]** | 今の数字・フェーズ・今クールのゴール | 下の「ひな型A」を埋めてメモに保存 | 月1回(月次レビュー時) |

**運用**: claude.ai で戦略相談を始めるときは、会話の最初に [ペルソナ] と [スナップショット] を続けて貼る。
Claude Code のセッションでは `CLAUDE.md` が自動で読まれるので [スナップショット] だけ貼ればよい。

## プロンプトの7要素

| 要素 | 内容 | 例 |
|---|---|---|
| 役割 | 誰として答えるか | 「あなたはYouTube運用の戦略コンサルタントです」 |
| 文脈 | 自分の状況 | [ペルソナ]+[スナップショット] |
| 依頼 | 何をしてほしいか1文で | 「動画企画を30本出してください」 |
| 制約 | 守ってほしい条件 | 「店の営業と両立できる週{{N}}時間の範囲で」 |
| 出力形式 | 表・箇条書き・字数 | 「表形式、タイトルは32字以内」 |
| 数と規模 | 具体的な数字 | 「10案」「12週間分」「200字で」 |
| 進め方 | 質問→骨子→合意→詳細化 | 「まず計画の骨子を提示し、私の合意を得てから詳細化して」 |

## 精度を上げる6つのコツ

1. **数字で指定する** — 「いくつか案を」ではなく「10案。うち攻めた案を3つ含める」。
2. **選択肢+推奨を求める** — 「2〜3案をメリデメ付きで。最後にあなたの推奨と理由」。丸投げより判断材料が残る。
3. **自分のデータを貼る** — アナリティクスの数字、過去のタイトル、店の繁閑。一般論を防ぐ最大の手段。
4. **プランファーストを明示する** — 長い成果物(台本・ロードマップ)は「骨子→合意→本文」の2段階を指示に書く。一発で全文を書かせると手戻りが大きい。
5. **反証させる** — 案が出たら「この案が失敗するとしたら何が原因か。上位3つと予防策を」と続ける。
6. **完成形で出させる** — 「そのまま使える完成ファイル/全文で。断片や『ここを修正』形式は不可」と明記する。

## 反復パターン(2往復目以降の定型文)

- 深掘り: 「2案目だけを、実行手順が分かるレベルまで具体化してください」
- 絞り込み: 「10案を『実現しやすさ×効果』の4象限に分類し、右上の3つだけ残してください」
- 視点変更: 「同じ依頼に、今度は{{視聴者代表 / 編集者 / キュレーター / 税理士}}の立場で答えてください」
- 攻撃: 「この計画の一番弱い前提を指摘し、崩れた場合の代替案をください」
- 翻訳チェック: 「このイタリア語を、ネイティブが違和感を持つ箇所に絞って添削してください(直訳調の指摘を優先)」
- 圧縮: 「ここまでの結論を、後日別の会話に貼れる形で500字に要約してください」← 会話の成果を持ち出すときに必ず使う

## モデルの使い分けの目安

- **上位モデル(Opus など)**: 戦略設計・ロードマップ・ステートメント執筆・アナリティクスの解釈・伊語の自然さレビュー。判断が絡むもの。
- **軽量・高速モデル**: タイトルの言い換え量産、文字起こし整形、タグ出し、翻訳の下書き。作業系。
- 長い相談は1会話で完結させず、「圧縮」パターンで要約を持ち出して新しい会話に貼り直す。

## ひな型B: 戦略パートナー化プロンプト(相談の起点)

テーマを決めて相談を始めるときの基本形。これ1つで大半の相談が回る。

```
あなたは、飲食店経営と並行して創作活動(YouTube・写真)を行う個人クリエイターを支援する戦略コンサルタントです。
専門は YouTube運用 / コンテンツマーケティング / 個人のマネタイズ設計 / 写真作品のプロデュース。

[ペルソナ]
[スナップショット]

## 今日の相談
{{相談テーマ。例: 伊語チャンネル2本のどちらを先に立ち上げるか}}

## 進め方
1. 判断に必要な情報が足りなければ、先に質問してください(最大5つ)
2. 私の回答を踏まえ、選択肢を2〜3案、それぞれメリット・デメリット付きで提示してください
3. 最後に、あなたの推奨案・その理由・最初の一歩(今週中にできる粒度)を示してください

## 条件
- 一般論ではなく、私の時間・機材・目標の制約に合わせること
- 「やらないことリスト」も必ず含めること
- 楽観シナリオだけでなく、うまくいかない場合の撤退基準にも触れること
- 設計判断の理由は詳しめに。必要なら言語学・物理・仏教哲学のアナロジーを使ってよい
```

## ひな型C: アイデア発散の汎用形(テーマを問わず使える)

```
[ペルソナ]
[スナップショット]

{{テーマ}}のアイデアを{{20}}案出してください。

## 条件
- 無難な案:攻めた案 = 7:3 の割合で混ぜる
- 各案は「一言タイトル+2行の説明+実行コスト(S/M/L)」の形式
- 私の既存資産(店・写真・語学・開発力)を使い回せる案を優先する
- 出し終えたら、私の制約に照らして上位3案を選び、選定理由を添えてください
```
