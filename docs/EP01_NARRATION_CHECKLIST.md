# EP01 ナレーション収録チェックリスト（VO台本）

> 手直し用台本(v2)の [ナレ]/[コフ] を章・ビート順に全抽出した収録用リスト。
> **収録メモ**: マスター進行台本の順（=この順）で一気に録るとトーンが揃う。
> 谷(⑥)はトーンを落とす。キー台詞(★)は別テイクも録る。各行頭の [ ] を録れたらチェック。
>
> トーン早見: OP=静→点火 / ①=明るく気持ちよく / ②=納得・静かに積む /
> ③=気づき / ④=手が動く / ⑤=整理→最後3秒だけ落とす / ⑥=谷・急がない /
> ⑦=山・歯切れよく / ⑧=前向き / ⑨=締め・湿っぽくしすぎない

## ④ ツール層の抽象化（約2分）

### ビートA 問題提起
- [ ] ③で、「コフの道具(ツール)は固定で、頭脳だけ差し替える」と言いました。ここで問題になるのが——その“同じ道具”を握る2つの頭脳が、別々の方言を喋ることです。
- [ ] Function Calling、つまりAIに自分の関数を呼ばせる仕組みは、AnthropicとOpenAIで形式が違う。道具は同じなのに、渡し方・受け取り方が噛み合わない。ここをどう揃えたか、の話です。

### ビートB 方言の違い ★核
- [ ] ★ 違いは大きく3つ。道具の定義の包み方、呼び出しの受け取り方、結果の返し方。特にいやらしいのが2つめで、片方は引数がオブジェクト、もう片方はJSON文字列で飛んでくる。そのまま使うと、片方は普通に動いて、片方は静かに落ちる。

### ビートC 素朴な解法のダメさ
- [ ] 素直にやると、形式ごとに処理を2回書くことになります。でもこれ、ツールを1個増やすたびに2箇所いじる羽目になって、すぐ食い違う。ツールは今10個近くある。これは無理だなと。

### ビートD 抽象化レイヤー
- [ ] ★ やったのは、間に翻訳レイヤーを1枚挟むこと。ツールは正規形で1回だけ定義する。名前、説明、引数のスキーマ、そして実際に動くハンドラ。あとはアダプタが、それを脳ごとの方言に翻訳して渡す。返ってきた呼び出しも、正規形に戻してから実行する。道具の定義は1つ。脳ごとの方言に翻訳してるだけなんです。

### ビートE テーゼと接続
- [ ] これ、③の話とそのまま地続きで——道具(人格の一部)は固定、方言への翻訳は差し替え可能な配管。だから頭脳を入れ替えても、コフは同じ道具を、同じように使える。
- [ ] じゃあ最後に、その2つの頭脳のどっちを使うか、誰がどう決めてるのか。次はルーティングの話です。

**別テイク（D核）**
- [ ] B: ツールは正規形で1回書く。各社の形式はアダプタに押し込める。

**別テイク（B罠）**

## ⑦ コールドロードと二段タイムアウト — 山（約1分30秒〜1分50秒）※テンポを戻す

> 数値テロップの実測値は本文に埋める：ping=2.5秒 / 生成=120秒 / コールドロード=[実測●●秒]

### ビートA 症状
- [ ] ハイブリッドにした後、地味に気持ち悪い挙動が残っていました。ローカルで動かしてるはずなのに、最初のメッセージだけ、勝手にクラウド側に切り替わる。2回目以降は普通にローカル。……なんで初回だけ?

### ビートB 原因（コールドロード）
- [ ] 原因はコールドロードでした。7Bクラスのモデルは、初回はメモリに読み込むだけで【実測 ●●秒】かかる。ところが僕のタイムアウトは、その読み込みを待ちきれずに先に発火していた。Ollamaは生きてるのに、「応答がない=落ちてる」と勘違いして、クラウドに逃げてたんです。

### ビートC 発想の転換 ★核
- [ ] ★ ここで気づいたのが、僕は2つの違うものを、1個のタイムアウトで測ってたということ。「生きてるか確認する」のと、「答えを待つ」のは、別の時間軸なんですよね。生存確認は速くていい。でも答えを待つのは、気長でいい。

### ビートD 実装（二段構え）
- [ ] やったことはシンプルで、タイムアウトを2段に分けただけです。まず軽いpingで「サーバ生きてる?」を【2.5秒】で確認。生きてれば、生成の方は【120秒】までゆっくり待つ。これで、コールドロード中でもpingは通るから、もう誤って逃げない。本当に落ちてる時だけ、ちゃんと速くクラウドへ切り替わる。

### ビートE 一般化・持ち帰り ★
- [ ] ★ で、これOllamaとかLLMに限った話じゃないんですよね。外部のサービスに頼るシステムなら、だいたい同じ。「生きてるかの確認」と「仕事が終わるのを待つ」を同じタイマーで測らない。これ、今日この動画で一個だけ持って帰るならコレでいいくらい、効きます。

**別テイク（C核）**
- [ ] B: 死活確認は速く、処理待ちは気長に。1個のタイマーで両方やろうとしたのが間違いだった。

**別テイク（E持ち帰り）**
- [ ] B: 外部依存があるなら、ヘルスチェックと処理タイムアウトは分ける。これだけで誤フォールバックは消える。
