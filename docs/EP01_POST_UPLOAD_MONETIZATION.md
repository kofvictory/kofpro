# EP01 撮影後の計画 — 編集 / アップロード / 収益化

> 撮影・収録が終わった後の全工程。編集(DaVinci Resolve)→ YouTube公開 → 収益化戦略。
> 前提: 素材はOBSで2880×1620キャプチャ / 出力1080p、ナレは別録り、対象は個人開発・
> エンジニア層(日本語・長尺)、シリーズ物(NPU化を縦糸に継続)。

---

## ⚠️ 事前確認: DaVinci Resolve と Snapdragon X

- DaVinci Resolve の Windows版は基本 x64。**Snapdragon X ではエミュレーション動作**になり、
  プレビュー/書き出しが重いことがある。まず**無料版で短い素材を試し書き出し**して実用速度か確認。
- 重くて作業にならない場合の代替(ARMネイティブで軽い):
  - **CapCut(PC版)** … 無料・テロップやトランジションが簡単・ARM快適
  - **Clipchamp(Windows標準)** … 無料・シンプル
  - **Premiere Pro** … ARMネイティブ対応が進行中(有料)
- 図解モーション(②三すくみ等)は編集ソフト内でも作れるが、凝るなら別ツール
  (After Effects/Motion/Canva/パワポ書き出し)でPNG/動画にして持ち込む方が早い。

## 1. 編集ワークフロー(DaVinci Resolve)

### 1-1. プロジェクト設定
- タイムライン解像度: **1920×1080** / フレームレート: **30fps**(OBS録画と一致させる)
- 色空間: Rec.709(YouTube標準)。凝らないなら初期設定のままでOK。
- 保存: プロジェクトは自動保存ON。素材は1フォルダに集約してから読み込む。

### 1-2. メディア整理(Mediaページ)
撮影素材をビン(フォルダ)で分類して読み込む。shot_listのA〜Hに対応:
- `A_画面録画` / `B_証拠(NPU0%・コールドロード)` / `C_コード差分`
- `D_図解` / `E_モーション` / `F_テロップ` / `G_ナレVO` / `H_BGM_SE`
- ファイル名は「章_ビート_内容」で。例: `05D_フォールバック主役.mp4`

### 1-3. 組み立て(Editページ) — 順序が命
**マスター進行台本(=章①〜⑨)の順に、まず“繋ぐだけ”のラフ編集**:
1. **ナレVOを先に全部並べる**(Gの通し録り)。これが動画の背骨=尺の基準。
2. ナレに合わせて、対応する画面録画(A)・図解(D)を上に乗せる。
3. この段階では細かい調整はしない。**通しで一度最後まで繋ぐ**(全体尺の把握が先)。

> 依存関係: 数値(B証拠)→ 図(D)→ ナレの数値読み(G)。⑦の「●●秒」は先に確定。

### 1-4. 寄り/ズーム(この動画の肝)
撮影は全画面(2880→1080)なので、**編集でクロップ+ズームして“寄り”を作る**:
- ①C **賢いモード切替の色変化(紫→オレンジ)**: 切替の瞬間にヘッダーへズームイン。
- ⑤D **フォールバックのチップが灰→琥珀に変わる瞬間**: チップにズーム。
- ⑦ **devターミナルの `POST ... in ●●ms`**: 数字にズーム(数値テロップの根拠)。
- やり方: クリップ選択 → インスペクタの Zoom/Position にキーフレーム。
  2880素材を1080に置いてあるので、**200%程度まで寄っても劣化が目立たない**(高解像度で撮った利点)。

### 1-5. 図解・モーション(D/E)
- ②三すくみの三角形、③2層レイヤー図(頭脳差し替え)、④翻訳レイヤー図、⑤フローチャート、
  ⑦二段タイムアウト図 → 静止画(PNG)で作り、Resolveでフェード/ワイプ点灯させるだけでも十分。
- ③の頭脳差し替えアニメは**⑧で再利用**(最初から流用前提で作る)。
- コフのモーション(E)は最小3種(まばたき/反応ポップ/うなずき)。アプリ側では作らず、
  ここでSVG/PNGに簡単な位置・スケールのキーフレームを付けて動かす。

### 1-6. テロップ(F)
- **装飾を1セットに統一**(フォント/色/縁取り)。★の決め台詞テロップは切り抜き/サムネに流用。
- 必須: 「もったいない」/「Vulkan・NPU(つもり)」+赤訂正線 / 数値(2.5s・120s・0%・コールド●●秒)/
  テーゼ引用「人格はモデルの中じゃなく外」/ 3つの持ち帰り。
- 数値テロップは**太く大きく**。曖昧にすると“持ち帰り”が消える。

### 1-7. 音(H) + 音声仕上げ(Fairlightページ)
- ナレVO: ノイズ除去 → コンプ → ラウドネス **-14 LUFS前後**(YouTube標準)に。
- BGM: OP=静→無音→一音で点火 / ⑥谷=BGMをほぼ抜く / ⑦⑨=気づき・締めのSE一音。
- **ナレとBGMの被り**: ナレ中はBGMを-18〜-20dB程度まで下げる(ダッキング)。
- 著作権: BGM/SEは**YouTubeオーディオライブラリ**や商用可のフリー音源(DOVA/甘茶/Epidemic等)を使う。
  ロックマンエグゼの音源・映像・キャラは**使わない**(語りのオマージュのみ)。

### 1-8. カラー(任意)
- 画面録画中心なので大きな色補正は不要。実写(ノートPCを開く等)があれば軽く整える程度。

### 1-9. 書き出し(Deliverページ)
- プリセット: **YouTube 1080p**
- コーデック: H.264 / 品質: 制限(ビットレート)なら **16〜20 Mbps**、または自動(高)
- 音声: AAC 320kbps / 解像度1920×1080 / 30fps
- 書き出し後、**必ず通し再生で確認**(音ズレ・テロップ誤字・無音区間)。

## 3. 収益化戦略

### 3-1. YouTubeパートナープログラム(YPP)の条件
- **登録者1,000人** かつ **公開動画の総再生時間4,000時間(直近12ヶ月)**、
  または ショート1,000万回(このチャンネルは長尺主体なので前者狙い)。
- ⚠️ ニッチな技術系は登録は伸びにくいが、**1本あたりの視聴時間が長く単価も高め**。
  長尺は再生時間4,000時間を稼ぎやすいのが強み。

### 3-2. 現実的な成長パス(このチャンネルの型)
1. **シリーズで“続きを見る理由”を作る**(NPU化・データ設計編…)。1本完結より積み上げが効く。
2. **1本に必ず“持ち帰り”を1つ**(EP01なら二段タイムアウト)。保存・共有される=拡散の燃料。
3. **検索に強いタイトル**(「Snapdragon NPU ローカルLLM」等、供給の少ない語)で長期の流入。
4. **オープン化**: コードをGitHub公開すると、開発者の信頼・被リンク・コメントが増える。

### 3-3. 収益源(広告だけに頼らない)
| 収益源 | 内容 | このチャンネルとの相性 |
|--------|------|------|
| **AdSense(広告)** | YPP達成後。長尺+高単価ジャンル | ○ ただし登録1000到達までは0 |
| **アフィリエイト** | Snapdragon機/周辺機器/書籍/クラウドのリンク | ◎ 概要欄に自然に置ける |
| **スポンサー** | 開発ツール/クラウド/AI企業のPR | ○ 登録数千でも技術特化なら来る |
| **メンバーシップ/サポート** | 限定進捗・ソース早期公開 | △ ファンが付いてから |
| **自作物(KofPro)** | 将来的にKofProを製品化/有料版 | ◎ 動画自体が製品のデモになる |
| **登壇/受託/転職価値** | ポートフォリオとしての価値 | ◎ 数字が小さくてもリターン大 |

### 3-4. このシリーズ特有の“強い”ポイント
- **NPUという縦糸**: 「未完の宿題」を掲げることで毎回“続きを見る理由”が生まれる。EP08のCTA設計が効く。
- **正直な失敗(⑥NPUの壁)**: 開発ドキュメンタリーは“成功自慢”より“正直な回り道”が信頼を生む。
- **持ち帰り知見**: エンジニアは「使える1個」があると保存・拡散する。1本1知見を厳守。
- **メタ構造**: コフが“自分の動画制作タスク”を管理している画(inboxキュレーション)は
  気づいた視聴者のコメントを誘発する仕掛け。

### 3-5. 指標の見方(公開後)
- 重視: **平均視聴維持率**(特に冒頭30秒の離脱)/ **クリック率(CTR)** / **平均視聴時間**。
- 登録者数より、**維持率とCTR**を先に改善する(サムネ・タイトル・冒頭の掴み)。
- ⑥の谷で離脱していないか、⑦の山で戻せているかを維持率グラフで確認 → 次回の構成に反映。
