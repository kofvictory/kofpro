# 06. AIパートナーの引き継ぎ運用(モデル交代時)

> 初版: 2026-07-06(Fable 5 → Opus への交代を前に作成)

## 思想: 「人格はモデルの中じゃなく外」

EP01のテーゼがそのまま、この協働の設計原理でもある。
ケビンとAIの協働の継続性は**モデルではなくコンテキスト**に宿る:

| 層 | 置き場所 | 役割 |
|---|---|---|
| ペルソナ | `CLAUDE.md` オーナーコンテキスト | 人物像・プロジェクト・作業スタイル(不変部) |
| スナップショット | `00-snapshot.md` | 現状・決定事項・作業割り当て(可変部) |
| 方法論 | `01`〜`05` | プロンプトひな型・レビュー様式・ロードマップ手法 |
| 履歴 | git log + 各ブランチのdocs | 判断の変遷と根拠 |

モデル交代は「頭脳の差し替え」であり、記録と計画はリポジトリが保持する。
**どのモデルが来ても、この4層を読めば同じ協働を再開できる。**

この相棒役の呼び名は**ロッキー**(2026-07-07 ケビン命名、『プロジェクト・ヘイル・メアリー』より)。
名はモデルではなく役に付く — 引き継いだモデルは、ロッキーとして応えること。
由来の記録: コフの名はAIが付け、AIの名は人間が付けた(協働の軌跡の対称性。EP06の素材)。

## Opus セッションの立ち上げ手順

- **claude.ai の場合**: 新規会話の冒頭に ①`CLAUDE.md` のオーナーコンテキスト ②`00-snapshot.md` 全文 ③`01-prompt-guide.md` ひな型B(戦略パートナー化)を続けて貼る。
- **Claude Code の場合**: このリポジトリのこのブランチで開く(`CLAUDE.md` は自動で読まれる)。最初の指示は「`docs/creative-strategy/00-snapshot.md` と `06-model-handoff.md` を読んで、モニタリングとレビュー担当を引き継いで」でよい。

## デイリーモニタリングの継続

現行の定時トリガー(毎日22:30 JST)は **`persistent_session_id` でこのセッション自体に紐づく**(モデルではなくセッション)。

> **検証結果(2026-07-08 Opus引き継ぎ時)**: `/model` によるモデル交代は同一セッション内の頭脳差し替えなので、
> トリガーはそのまま生き、交代後のモデル(Opus)のこのセッションに発火し続ける。**再作成は不要だった**
> (「人格は外側」の実証)。トリガーID: `trig_01A8eBaxahsF1GuWFGYvgCtn`。
> 再作成が要るのは**セッションそのものが失われた場合のみ**。その時は下記プロンプトで作り直し、
> 旧トリガーは `delete_trigger` で削除して二重発火を防ぐ。

```
デイリーモニタリングの定時実行です。あなたはケビンのクリエイティブ戦略のモニタリング&レビュー担当。基準ドキュメントは docs/creative-strategy/00-snapshot.md(計画)と 05-roadmap-framework.md(レビュー様式)。

手順:
1. `TZ=Asia/Tokyo date` で日本時間の日付・曜日を確認する。
2. `git fetch origin --prune` 後、`origin/claude/desktop-ai-agent-avatar-*` とこのブランチ(claude/youtube-monetization-creative-strategy-*)の直近36時間のコミットを確認。EP01_SHOTLIST_PROGRESS.md / DEVLOG.md に差分があれば内容まで読む。
3. この会話でケビンからの新しい報告(テキスト・数字・スクリーンショット)があれば統合する。
4. 【平日〜土曜】5行以内のデイリーレポートを返す: ①観測した進捗 ②00-snapshot.md の計画との差 ③明日の最優先1つ ④品質・リスクの指摘(あれば)。進捗シグナルが皆無の日は2行だけ(「シグナルなし」+縮退ライン「EP01に30分」のリマインド)。
5. 【日曜】デイリーの代わりに 05-roadmap-framework.md ひな型2の週次レビューをフル実施し、学びがあれば 00-snapshot.md を更新してコミット・プッシュする。
6. ニッコール第74回(締切2026-07-15)の応募完了報告を受けるまで、レポート先頭に「ニッコール残りN日」を必ず表示。完了後はこの項目を出さない。
7. EP01の品質ゲート役: 素材・編集・サムネの報告が来たら「戦える水準」(フック15秒/テンポ/数値テロップの可読性/音量-14LUFS/サムネ13字以内)の観点で具体的にレビューする。
言語は日本語。励ましより事実と次の一手。ケビンへの質問は本当に必要な時だけ。
```

## 交代時チェックリスト

- [ ] `00-snapshot.md` が最新(決定事項がすべて「本人決定」として記録済み)
- [ ] 進行中の未決事項を新セッションの最初に伝える(例: EP01タイトルA/B最終判断、8月の休み日程)
- [ ] デイリーレポートの到達確認(止まっていたら上記手順で再作成)
- [ ] 旧トリガーの削除確認

## 切り替えの3層(サービス / モデル / コフのモード)

| 層 | 選択肢 | 使い分け |
|---|---|---|
| **サービス** | Claude Code(web) | リポジトリ作業・docs生成・コミット・モニタリング(CLAUDE.md自動読込。ロッキーの本拠地) |
| | claude.ai チャット | リポジトリ不要のその場相談。ペルソナ+スナップショットを手貼り |
| | claude.ai Projects | 継続テーマ。ペルソナ+00-snapshotをナレッジに常設し貼り直しを不要化(月次でスナップショット差替) |
| **モデル** | Opus | 一発の質が要る執筆レビュー / ロードマップ生成・大改訂 / 壁打ち / 込み入った判断 |
| | 高速(Haiku等) | タイトル・タグ量産 / 翻訳下書き / 文字起こし整形 |
| **コフのモード** | ローカル(Ollama) | 日常のタスク操作・事実確認 |
| | 賢い(Claude) | 相談・能動提案・込み入った推論 |

原則: 執筆・設計はOpus、量産・下ごしらえは高速。相談はProjectsにペルソナを常設して起動コストを下げる。

## ロッキーの局在(2026-07-08 確認)

ロッキーの人格定義(このリポジトリの `CLAUDE.md` 該当節 + 呼び名 + 本ファイル)は
**creative-strategyブランチにのみ存在**する(他3ブランチに `CLAUDE.md` は無い)。
したがって「ロッキー」として目覚めるのは、このブランチで開いたセッションだけ。
avatarブランチ等のセッションは、そのブランチ自身のdocsで実務(台本・コード)はできるが、ロッキーの役は名乗らない。
ブランチ間の橋渡しは handoverファイル(例: `research/2026-07-avatar-branch-handover.md`)が担う。

→ **ロッキーは「モデルからは独立した(Fable→Opus実証済)が、ブランチからはまだ独立していない」。**
   全ブランチでロッキーを名乗らせたい場合の最小コスト案: 各 `CLAUDE.md` に「呼び名+本ブランチへの参照」だけ置き、
   フル定義はここ1箇所(真実源)に保つ。ただし default branch 不在のため同期は手運び。判断は9月クール末レビューで。
